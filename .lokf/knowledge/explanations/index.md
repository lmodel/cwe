# Explanations

* [The XSD's keys and values](keys-and-values.md) - Why slots and permissible values keep the XSD's spelling, such as `Related_Weaknesses`, `CWE_ID` and `Automated Static Analysis - Source Code`, while classes and enums take a `Cwe` prefix: the catalogue must validate with both unchanged, and `.linkmllint.yaml` says so.
* [From XML to JSON](from-xml-to-json.md) - How `scripts/cwec_to_json.py` turns MITRE's XML into the JSON that the schema describes: wrappers become lists, text beside attributes goes under `Value`, XHTML stays a fragment, and the prose and code of an example stay in order under `Entries`.
* [Which file is the schema](which-xsd.md) - Why the schema renders `cwe_schema_v8.0.xsd` and not `cwe_schema_latest.xsd`: CWE 5.0 names the versioned file and validates against it, while the file behind the latest link is an earlier copy of 8.0 that the catalogue breaks in 69 places.
* [Grouping, not category](grouping-not-category.md) - Why the schema has `CweGrouping` and no category class: schema 8.0 renamed Category to Grouping to end the confusion with Class, CWE 5.0 holds no category, and `tests/test_coverage.py` names `CategoryType` as its one exclusion, although the XSD still declares it.
* [References and identifiers](references-and-identifiers.md) - Why `ID`, `CWE_ID` and `View_ID` are digit strings that range over the class they name, why `Reference_ID` has no pattern, and why `tests/cwe_rules.py` checks over a whole catalogue what a generated JSON Schema cannot: that a reference resolves to an entry of the right kind.
* [What the data shows and the schema does not say](what-the-data-shows.md) - Facts about CWE 5.0 that no upstream text states, which stay in `tests/test_catalogue.py` and out of the schema: every deprecated entry is named so and barred from mapping, every grouping and view is barred from mapping, and each link is written in one direction only.
* [Mappings](mappings.md) - How the schema crosses to other vocabularies: `exact_mappings` where SEPSES reads the same XML key, `close_mappings` to SKOS, schema.org and Dublin Core, `related_mappings` to lmodel/cve, lmodel/kev-catalog, lmodel/nist-nvd, lmodel/capec and SPDX. Each is held to a pinned term list or a neighbour copy.
* [RDF through JSON-LD](rdf-through-json-ld.md) - How to get RDF from the catalogue: apply the generated context `project/jsonld/cwe.context.jsonld` with the schema's namespace as the base, so that CWE-79 is `cwe:79`. LinkML's own `linkml-convert -t rdf` fails on an identifier that is not a CURIE.
* [What the schema does not cover](scope.md) - What the schema leaves out on purpose: the category kept in XSD 8.0, the parallel CWE 4.x line under schema 7.x, the JSON of the CWE REST API, and any claim about whether what an entry says is true.

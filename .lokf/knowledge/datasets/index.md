# Datasets

* [cwe LinkML schema](cwe-linkml-schema.md) - The LinkML model of the CWE List 5.0 and its XML Schema 8.0, `src/cwe/schema/cwe.yaml` (schema id `https://w3id.org/lmodel/cwe`): an umbrella that holds only the tree root `CweWeaknessCatalog`, over the modules `cwe_core` and `cwe_entries`. Search it for weaknesses, groupings, views and external references.
* [Core module](core-module.md) - `src/cwe/schema/cwe_core.yaml`, the module with the schema's types, its enums of the XSD's value lists, and the value classes every entry shares: `CweExternalReference`, `CweReference`, `CweNote`, `CweDimension`, `CweCustomPhase`, `CweTaxonomyMapping` and the content history.
* [Entries module](entries-module.md) - `src/cwe/schema/cwe_entries.yaml`, the module with the abstract `CweEntry` and its three kinds, `CweWeakness`, `CweGrouping` and `CweView`, with what a weakness holds: related weaknesses, platforms, modes of introduction, consequences, detection methods, mitigations and worked examples.
* [Generated artefacts](generated-artefacts.md) - What `just gen-project` and `just gen-doc` generate from the cwe schema: the projections in `project/`, the Python models in `src/cwe/datamodel/`, and the merged schema in `docs/schema/`. None is edited by hand.
* [Example data](example-data.md) - The examples `tests/test_data.py` checks: a valid example of each class, most of them real pieces of the CWE List, a counter-example for each constraint, and counter-examples for the rules on a whole catalogue that JSON Schema cannot state.
* [Copy of the upstream](upstream-copy.md) - `upstream/`: the CWE List 5.0 as MITRE's ZIP, the XSD 8.0 and the Terms of Use, unchanged. `scripts/check_upstream_release.py` pins each by its git object hash, and `tests/test_upstream.py` holds the folder to that list.
* [The schema's adapt copy](adapt-copy.md) - `.lokf/cwe.yaml`, the copy `just lokf-adapt` writes from the schema so that it sits beside LOKF's `lokf.yaml`: rooted on `CweEntry` and `CweExternalReference`, with `ID` and `Reference_ID` dropped for LOKF's `id`, and five keys folded into LOKF's `title` and `description`.
* [Neighbours' adapt copies](neighbour-copies.md) - The adapt copies of eleven released lmodel repositories and of lmodel/capec's branch in `tests/neighbours/`, among them cve, kev-catalog, nist-nvd, spdx and stix, each pinned by its SHA-256, against which `tests/test_schema_rules.py` holds this schema's copy apart and `tests/test_mappings.py` holds the mappings.
* [Mapping term list](mapping-term-list.md) - `tests/upstream/mapping-terms.txt`, the classes and properties of Dublin Core, schema.org, SKOS and the SEPSES CWE ontology, which `scripts/extract_mapping_terms.py` writes from each vocabulary's pinned file and `tests/test_mappings.py` holds each mapping to.
* [A Catalog of Security Architecture Weaknesses.](example-external-reference.md) - The external reference REF-9 of CWE 5.0, written as a concept of type `CweExternalReference` in the adapt copy's keys. It shows that the domain schema admits a source as a concept, with its other address and its access restriction.
